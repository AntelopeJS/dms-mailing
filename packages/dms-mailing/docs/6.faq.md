# FAQ

## My code gets a send with the status `suppressed`

The recipient is on the [suppression list](/docs/modules/mailing/usage/suppression-list): a hard bounce, a spam complaint, an unsubscription or a manual entry. `error` names the reason as an i18n key (`$dms_mailing.errors.suppressed.hard_bounce`, `….complaint`, `….unsubscribe`, `….manual`). Do not retry: reactivate the address first if it is valid again.

## A send was refused for a missing variable

**Settings › Delivery guards › Missing variables** is set to **Refuse the send**, and the call did not pass a required variable. Pass it in `variables`, or switch the guard to **Send anyway** to send with blanks. For a `marketing` template, `unsubscribeUrl` and `preferencesUrl` are required when its footer shows those links.

## My provider's webhook calls are refused

**Settings › Provider & webhook › Webhook status** shows the last refused call and its reason:

| Reason | Fix |
| --- | --- |
| `missing_secret` | Send the `x-mailing-webhook-secret` header. Most providers cannot add one: put a [relay](/docs/modules/mailing/extending#relaying-a-provider) in front. |
| `bad_secret` | Copy the current secret again (rotating invalidates the old one). A workspace that has never opened a mailing page or sent anything has no secret yet. |
| `invalid_event` | The body is not in the [generic event format](/docs/modules/mailing/extending#webhook-contract). |

## The webhook URL points to localhost

The URL is built on the DMS `clientBaseUrl`. Set it to the public origin of the dashboard in the `dms` module's config.

## The logo is missing from my e-mails

The logo is the DMS branding's light logo at an absolute public URL. It is left out on a `localhost`, private-IP or `.local` origin, and for SVG files, which Gmail and Outlook refuse. Use a PNG and a public `clientBaseUrl`.

## A recipient got English instead of German

The template has no `de` version, so the module sent the workspace's fallback locale. The send log shows it (`DE asked`), and the editor offers to create the missing locale.

## Do edits change what customers receive?

No. Edits stay in a draft until you publish; real sends always use the published version, and every send records the version it used.

## I upgraded from 0.3: what changed?

The v2 redesign neither reads what 0.3.x wrote nor takes its calls:

- **Webhook URL.** `POST /api/mailing/events/<provider>`, with the tenant in
  the body, is gone. Copy the URL **Settings › Provider & webhook** shows
  (`/api/mailing/events/<provider>/<tenantId>`) into the provider again.
- **Settings writes.** `POST /api/mailing/settings` is gone: send the changed
  fields with `PUT /api/mailing/settings`. A write carrying a read-only field
  (`webhookUrl`, `provider`) is refused.
- **Categories.** The settings take `categories` as an array only, no longer
  as its JSON text, and always with the `marketing` category (it can be
  renamed, not removed: campaign rules depend on it).
- **Interface.** The module implements `@antelopejs/interface-dms-mailing`
  0.7, whose `SendStatus` adds `suppressed`.
- **Data.** A 0.3.x database is not read any more (settings rows without the
  tenant key, templates without version numbers, sends without a stage):
  start the module on an empty database.
